# web — air-quality

The public site. Astro, static output, no runtime backend.

```bash
npm install
npm run dev      # http://localhost:4321
npm run build    # -> dist/
npm run check    # TypeScript + Astro diagnostics
```

## Where the data comes from

`public/data/` is generated by the Python pipeline, not by hand:

```bash
uv run twair export web
```

That writes four things:

| Path | What | In git |
|---|---|---|
| `public/data/meta.json` | stations, measurands, provenance | yes |
| `public/data/l0/*.json` | station-month means, one file per measurand | yes |
| `public/data/story/*.json` | the per-chapter payloads | yes |
| `public/data/l1/*.parquet` | station-day means, ~55 MB | **no** |

L0 and the story payloads are committed because the site cannot render without
them and they are small. L1 is regenerated on demand and served from a data
host; committing it would add tens of megabytes per rebuild. L2 — the full
hourly record — never comes here at all.

CI has no copy of the 341-million-row store, so **refreshing the site's data is
a local step followed by a commit**, not something the deploy workflow can do.

## Reading a null

Every L0 cell has a `mean` and an `n_days`. A null `mean` means one of two
different things and `n_days` is what separates them:

- `n_days == 0` — the station was not measuring that month.
- `n_days > 0` — the aggregate existed and was **withheld**, because coverage
  fell below the threshold and a mean drawn from a handful of days would be
  biased.

Both must render as a break in the line. Nothing on this site interpolates
across a gap; the gaps are findings.

## Charts

There is no charting library. Charts are SVG built in Astro frontmatter, so
they are in the HTML on first paint, work without JavaScript, and print. The
one behaviour worth having a library for — breaking a line at a null instead of
bridging it — is the one most libraries get wrong by default, so `lib/chart.ts`
does it explicitly.

## Deployment

`.github/workflows/pages.yml` builds and publishes to GitHub Pages. It is inert
until the repository has a remote and Pages is set to "GitHub Actions" in
Settings. `PUBLIC_SITE_URL` and `PUBLIC_BASE_PATH` are derived from the
repository name in CI; set them yourself for a custom domain.
